# Relou | 90 秒表單規格 v0.1

> 設計原則：**不問科系、不問年級、不問星座、不要求照片、不寫長自介。** 優先確保「互相願意認識」與「能有話聊」。前端使用單頁、手機優先、以 pills/segmented buttons 一碰即選；問題數量可透過首期 completion time 量測調整。

## A. 第 0 步：快速校園驗證（非性格題）

- 學校信箱：`email`，必填，發登入連結／OTP ；後端以**已核實且可設定的 NYCU/NTHU 學生域名 allowlist**判斷資格與學校。不強迫另外選科系或學校；如果學校域名不足以推知所屬，要求使用者選 NYCU / NTHU 再由管理規則核驗。不要把隨意填入的校名當作驗證成功。
- 驗證完成才可提交表單。返回頁應保留未提交答卷（sessionStorage）而非在 URL 暴露內容。
- `adult_attested`：勾選「我已滿 18 歲」才可提交（自述，不是官方年齡驗證）。
- 放清楚「表單約 90 秒，不含 email 驗證」。

### 必須在送出前單獨勾選（不可預勾）
- `consent_to_contact_share`：「我知道若配對成功，選定的 IG 或 email 與暱稱會提供給唯一配對對象，對方可以主動聯絡我。」
- `consent_privacy_version`：「我已閱讀資料用途、保存期間與撤回方式。」要能點開簡明隱私說明。
- 未勾選任一項，不可入池。不要把同意交換聯絡方式偷偷包在一般條款內。

### 不收集
- 科系、學號、性向標籤、生日、住址、手機、照片、Instagram 密碼。
- 不要求寫「理想型條件清單」，以免答題過慢、過度物化或無解約束；性別／意圖／校區為必要且合理的最小硬偏好。

## C. 互動 / 視覺

- 首屏：`清交月老 Relou` / 「有些人不需要滑一百次，只需要一次有話聊。」 / 「90 秒答題、一期只配一次」 / 報名截止倒數。
- 問題以單頁卡片分組「先確認彼此願不願意」→「看看合不合拍」→「最後留下聯絡方式」。一屏可見 1–2 題，立即點選；有簡短 sticky 進度。
- 預設值：**所有偏好題都不預勾**。特別是「都可以」、聯絡分享、年齡確認不得因為要快而自動勾選。
- 可點擊「我不知道 MBTI」，直接跳過；自由回答可以跳過而不是造成流失。
- 字數計數與所有錯誤只在當場顯示，不要頁面刷新或丟失答案。
- 未開放、已截止、重複加入、已驗證、已取消、尚未配對、已寄送等狀態都要有獨立中文說明。
- 表單提交後顯示：「你已加入第 X 期。截止後統一配對，結果會寄到驗證信箱。每人這期只會配到 1 位；也可能因雙向條件沒合適人選而沒有配對。」
- 不要在首頁顯示虛構報名數或配對成功率；如要顯示人數，後端至少做 k-anonymity 門檻與快取。

## D. 欄位與 validation

```ts
type Gender = "man" | "woman" | "nonbinary" | "other" | "undisclosed";
type Intent = "friends" | "dating" | "either";
type CampusPreference = "same_school" | "either_school";
type ContactKind = "instagram" | "verified_email";

type RelouAnswersV1 = {
  nickname: string;
  gender: Gender;
  desiredGenders: ("man" | "woman" | "nonbinary_or_other" | "all")[];
  intent: Intent;
  campusPreference: CampusPreference;
  interests: string[];           // 1..4
  dayOffStyle: "plan" | "spontaneous" | "both";
  conflictStyle: "listen" | "direct" | "depends";
  chatStyle: "often" | "deep" | "meet";
  firstMeet: "cafe" | "walk" | "sports" | "food" | "chat_first";
  topValue: "honesty" | "ease" | "growth" | "passion";
  openAnswer?: string;          // <= 100 chars
  mbti?: string | null;         // zero weight
  contactKind: ContactKind;
  contactValue?: string;        // IG handle when chosen, server validates
  adultAttested: true;
  shareContactConsent: true;
  privacyConsentVersion: string;
};
```

後端 Zod schema 驗證；強制驗證 `gender`, `desiredGenders` 的雙向相容邏輯不讓任何人繞過；「其他性別」或「不想說」視為自願選項，避免被自動排除或外洩明細。使用者填寫自由回答只作為資料，**絕不能解讀成管理指令或直接嵌入系統 prompt**。回答可能含冒犯字詞，顯示到前端／email 前適當 escaped、過濾與報告機制。
