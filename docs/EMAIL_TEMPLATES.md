# 結果信模板與寄送規則

模板版本：`result-v2`。參與者分享同意版本：`2026-10-29-v3`。只有配對結果，不寄報名確認、OTP 或驗證信。

## 三種情境

| 情境 | 主旨 | 發送時機與內容 |
| --- | --- | --- |
| 提前配對成功 | 青椒配對｜{月份期次}｜提前配對成功 | 經 90 分以上與雙向硬條件／共同具體興趣檢查後，確定配對；只通知該一對，不寄落單信 |
| 期末配對成功 | 青椒配對｜{月份期次}｜配對成功 | 管理員確認主要結算後，通知尚未提前配對的成功者 |
| 本期未配對 | 青椒配對｜{月份期次}｜配對結果 | 只在主要結算後通知本期未配對者；不附候選名單，說明次月須重新報名 |

## 成功信的閱讀順序

1. 期次、稱呼、對方暱稱及提前／期末結果，不在主旨放個資。
2. **你們的共通點**：最多三項。先列共同的標準興趣（不含「其他」或自填內容），再列雙方完全一致、可用固定文字摘要的初次互動／聊天節奏／重視的相處原則。沒有明確一致時直接說明，不猜測或編造。摘要不代表成功率或關係保證。
3. **對方同意分享的聯絡方式**：只顯示一種。IG 顯示 handle 與固定 instagram.com 個人頁；選擇分享 Email 才顯示本人提交的通知地址與 mailto 連結。後端拒絕缺分享同意、不合法 IG 或不相符 Email。
4. **可以這樣開始聊**：一則可複製的招呼，最多引用一個具體共同興趣；沒有共同興趣就問近況，不假裝知道對方經歷。
5. 聯絡自由、不強迫回覆、公開場所見面、不提供金錢／密碼／證件、不轉傳聯絡方式、身分與信箱未驗證的提醒。
6. 誤收信、更正、刪除或停止後續通知的人工核對聯絡窗口。不是只憑 Email 字串即可刪除資料的公開端點。

**不出現**：私人通知 Email（除非本人選擇分享）、自己的 IG、學校／學位／系所、性別／意願、MBTI、完整自由回答、自填興趣原文、分數或其他候選人。新分享同意明列共通點摘要；任何一方是舊版同意時，僅保留原已允許的共同標準興趣，不擴大分享其他回答摘要。

## 格式與方法

- 寄件者顯示 `青椒配對`，實際 From 必須等於已配置 Gmail SMTP 帳號。Reply-To 為主辦者 SUPPORT_EMAIL。每封只有一個 To，沒有 CC/BCC。
- 簡單單欄 HTML，最大 600px，系統字型、內嵌樣式、清楚小標；不放宣傳圖、追蹤像素、外部圖片或腳本。所有動態文字都 HTML escape；聯絡連結只有固定 IG／經驗證格式的 mailto。
- 同一份內容同時產生 HTML 與純文字。SMTP 使用 multipart/alternative，純文字先、HTML 後，UTF-8 base64、76 字元 body 換行；中文主旨依 RFC 2047 分段，encoded-word 不超過 75 字元且不切斷 UTF-8 字元。參考 [RFC 2046](https://www.rfc-editor.org/rfc/rfc2046.html)、[RFC 2047](https://www.rfc-editor.org/info/rfc2047/)。
- 配對提交時將主旨、純文字、HTML 及模板版本一起凍結到 outbox。重試使用同一份已存內容，不在重試時重新挑對象／重製模板。原有 queued 舊信不批次改寫，HTML 為 null 時維持純文字寄出。既有 dedupe key 保持不變，避免因改模板再次通知同一人。
- Gmail 250 只代表伺服器接受，不等於收件匣送達。uncertain/sending 不能盲目自動重寄。全域 dry-run、寄信開關、期次 pause、每封信 claim 與稽核仍有效。

## 合成預覽（不寄信）

執行 `pnpm run preview:emails`，產生：

- `private/email-previews/index.html`：索引，明確標示合成資料。
- `early-ig.html/.txt/.eml`：提前成功、分享 IG。
- `final-email.html/.txt/.eml`：期末成功、主動分享 Email。
- `unmatched.html/.txt/.eml`：未配對。

資料均為合成暱稱及 example.invalid 地址；不要改成真人資料再放進公開 Git。可用 `python -m http.server 8790 --bind 127.0.0.1 --directory private/email-previews` 本機預覽，或在郵件軟體開啟 EML 檢查；開啟 EML 不等於已寄出。

已驗證：模板／個資邊界／HTML escape／舊同意版本／禁止提前落單、UTF-8 主旨與 multipart round-trip、Python 標準 email parser 無格式 defects、390px 與 1440px 瀏覽器視覺／連結。這不是 Gmail、Outlook、Apple Mail 實機收件驗證；真正接受／收件匣呈現與垃圾信分類仍需經批准的 Gmail 測寄。
