## Remaining differences and acceptance limits

- Automatic suspicious/spam detection and event counters are absent. Admin explicitly says untracked instead of inventing zero. Manual exclusions exist; a dedicated flagged-review queue remains incomplete against ANALYTICS_ADMIN_SPEC.
- Matching preview has mean/median/count/rate, but not the requested percentile histogram and detailed anonymous exclusion report. Score components are computed but not persisted separately.
- The form has an “其他” interest chip without the optional custom short interest text. Optional semantic/MBTI scoring remains off/zero as required.
- Some administrative state changes write their audit event after the mutation rather than in the same atomic batch. A database failure between them can leave an audit gap; settlement/purge have transactional audit.
- Solver refuses >300 candidates; Workers Free CPU/query budgets have not been capacity-validated. Gmail SMTP sending limits and school-account app-password eligibility must be verified before a real round.
- Browser verification is synthetic desktop interaction, not human-study evidence or physical-device acceptance. The browser viewport override did not actually change the rendered width (read-back stayed 1280px); mobile acceptance remains unverified.
- Live authenticated dashboard access requires an operator to complete Access PIN login. Synthetic authorization tests do not prove the external login flow.
- Gmail SMTP credentials, controlled live result test and inbox delivery evidence are still required. Keep EMAIL_DRY_RUN=true, EMAIL_ENABLED=false and no OPEN round until ready.
- There is no lint script/configuration in this repository. TypeScript checking, tests and build are the available automated checks.

## Reproduce local checks

Use Node 22.13+ (or Node 24) and Corepack/pnpm 11.25.0:

```sh
pnpm install --frozen-lockfile
pnpm typecheck
pnpm test
pnpm build
pnpm demo
```

The demo uses only `wrangler.local.jsonc`, a separate local D1 database, official Turnstile test keys and a clearly marked synthetic round. It never uses remote D1 or sends mail. Admin authentication is never bypassed by demo configuration. Integration-test authentication mocking is limited to tests/database.test.js.

## Gmail setup after deployment

Set a Google account app password through the interactive secret command, never in chat, source code, or command arguments:

```sh
pnpm exec wrangler secret put GMAIL_SMTP_APP_PASSWORD
```

`GMAIL_SMTP_USER` and `EMAIL_FROM` must be the same authorized mailbox. Google Workspace/school policy may restrict app passwords. Keep dry-run on until a controlled test is explicitly approved. There is no signup mail, live-send scheduler, or automatic OPEN action.

After configuration and an approved controlled result test, deliberately set EMAIL_DRY_RUN=false and EMAIL_ENABLED=true and deploy. Admin RESUME/SEND still require operator actions; timeouts remain uncertain. Gmail acceptance (`250`) is not proof of recipient inbox delivery.
